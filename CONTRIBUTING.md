# Contributing Rules

This is just the convention guide for our team so we don't break the code and pattern.

## Branches
- Never push directly to `main`.
- Create a new branch for your task. 
- Name it like `feat/your-feature` or `fix/what-you-fixed`.

## Commits
We are using basic [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/). Keep it simple:
`type(scope): message`

The `(scope)` helps show what part of the project you changed, like `(frontend)` or `(backend)`.

Main types you can use:
- `feat`: for new things
- `fix`: for bugs
- `docs`: for text changes
- `chore`: for config stuff

Example:
`feat(frontend): create login page`

## Pull Requests
1. Push your branch.
2. Open a PR to `main`.
3. Ask someone in the group to review and approve it.
4. Merge it!
